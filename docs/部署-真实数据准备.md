# 部署前必读：真实数据怎么来

三个已验证的沪深300策略（LightGBM/XGBoost/集成）和30支候选池LightGBM策略，都依赖一批预先生成好的真实历史数据和训练好的模型文件。这些文件**没有进 git**（体积大，`backend/.gitignore` 排除了整个 `backend/data/`），Docker 镜像构建时也不会自动生成它们。

## 两条部署路径

**路径A · 最小代价（`docker compose up` 直接起，不需要任何准备）**

系统会自动检测这些文件是否存在：不存在时，会跳过注册那3个沪深300策略和相关的模型预热，服务照常启动，通用股票目录、AI 投研、策略中心等其它功能不受影响。适合先把系统跑起来看看、或者只关心通用功能的场景。

**路径B · 完整真实策略（先跑一条准备命令，再 `docker compose up`）**

想要三个沪深300策略和30支候选池策略真正可用，需要先在宿主机（不是 Docker 容器里）生成好数据和模型，见下文。生成一次之后长期有效，之后正常 `docker compose up` 就会带上这些真实策略。

## 为什么不能自动生成

- 生成过程需要 `baostock`（真实行情数据源）和 `xgboost`/`lightgbm`（模型训练），这些是可选依赖（`real-data`/训练相关），不在生产 Docker 镜像的最小依赖集里。
- 抓取+训练总耗时较长（几十分钟到数小时，取决于机器和网络），不适合放进 `docker build` 或每次 `docker compose up`。
- 更现实的做法：**在宿主机或专门的训练环境生成一次，然后把结果放进 Docker 的数据目录**，之后只要不清空这个目录，就不用重新生成。

## 需要准备的文件清单

放在 `backend/data/` 下（相对仓库根目录 `PatienceQuant/backend/data/`）：

| 文件/目录 | 用途 | 生成脚本 |
|---|---|---|
| `csi300_constituents.parquet` | 沪深300真实成分股名单 | `scripts/fetch_csi300_universe_history.py` |
| `csi300_universe_history.parquet` | 沪深300全部300支真实历史行情 | `scripts/fetch_csi300_universe_history.py`（同一个脚本一起产出） |
| `real_csi300_index.parquet` | 真实沪深300指数点位（用于回测超额收益对照） | `scripts/fetch_real_csi300_index.py` |
| `csi300_lightgbm_ensemble_model_walkforward/` | LightGBM沪深300策略的训练好的模型（按年/种子分目录） | `scripts/build_csi300_regression_training_dataset.py` → `scripts/train_csi300_lightgbm_ensemble_walkforward.py` |
| `csi300_xgboost_ensemble_model_walkforward/` | XGBoost沪深300策略的训练好的模型 | 同上数据集 → `scripts/train_csi300_xgboost_ensemble_walkforward.py` |
| `broad_universe_history_extended.parquet` | 30支候选池策略的历史行情（2010年至今，覆盖早年样本不足的问题） | `scripts/fetch_broad_universe_history_extended.py` |
| `broad_regression_h90_ensemble_model_walkforward/` | 30支候选池LightGBM策略的训练好的模型 | `scripts/build_broad_regression_h90_extended_training_dataset.py` → `scripts/train_broad_regression_h90_ensemble_walkforward.py` |

## 生成步骤（宿主机 / 训练环境，不在 Docker 里跑）

一条命令跑完全部8步：

```bash
cd PatienceQuant/backend
pip install -e '.[real-data]'          # baostock是可选依赖，xgboost/lightgbm已在主依赖里
bash scripts/prepare_real_data.sh
```

`prepare_real_data.sh` 按顺序跑下面这些脚本，每一步都按 symbol/年份维度增量写入、跳过已完成的部分，可以安全中断后重跑；脚本本身也是幂等的，重复执行不会把已经生成好的部分重新算一遍：

```bash
python scripts/fetch_csi300_universe_history.py       # 生成 csi300_constituents.parquet + csi300_universe_history.parquet
python scripts/fetch_real_csi300_index.py              # 生成 real_csi300_index.parquet
python scripts/build_csi300_regression_training_dataset.py
python scripts/train_csi300_lightgbm_ensemble_walkforward.py
python scripts/train_csi300_xgboost_ensemble_walkforward.py
python scripts/fetch_broad_universe_history_extended.py
python scripts/build_broad_regression_h90_extended_training_dataset.py
python scripts/train_broad_regression_h90_ensemble_walkforward.py
```

训练脚本（`train_*_walkforward.py`）耗时最长，是逐年滚动训练多个随机种子的模型，整体预计几十分钟到数小时，取决于机器性能和网络状况，请预留足够时间。

## 交给 Docker 部署

`docker-compose.yml` 把 `backend` 服务的数据目录改成了**绑定宿主机目录**（不是具名卷）：

```yaml
volumes:
  - ./backend/data:/app/data
```

也就是说：只要上面的文件/目录出现在 `PatienceQuant/backend/data/` 下（无论是在这台机器上生成的，还是从别处复制过来的），`docker compose up` 启动的容器就能直接用，不需要 `docker cp`、不需要进容器手动放文件。

## 通用股票目录不需要这一步

上面这些文件只影响"沪深300策略集"和"30支候选池策略"这两条独立的真实数据管道。通用股票目录（自定义股票池、股票搜索等次要功能）走的是另一条路径——运行时直接连 baostock 实时查询（见 `app/data/baostock_provider.py`），不需要预生成任何文件，`DATA_MODE=real` 时自动生效；baostock 连不上时会自动回退到本地50支真实公司的离线数据，不影响启动。

## OpenAI Key 不需要重启

`OPENAI_API_KEY`/`OPENAI_BASE_URL`/`OPENAI_MODEL` 现在可以直接在前端"AI 投研"页面右上角"API 设置"里配置，保存后立即生效，不用改 `.env`、不用重启 Docker。`.env` 里配的值仍然作为没在前端配置过时的默认值保留。
