# 部署与数据准备

## 数据从哪里来

代码仓库不包含数据。`backend/data/` 需要的全部数据打成一个**数据包**（约 1.2GB），作为 GitHub Release 附件发布：

```bash
make data          # 等同于 python scripts/fetch_data.py
```

脚本只用 Python 标准库：下载（中断后可续传）、校验 sha256、解压到 `backend/data/`。数据包的内容：

| 目录/文件 | 内容 |
|---|---|
| `market/a_share/daily/` | A 股日线与复权因子，2010-01-04 ～ 2026-09-23，4,063 个交易日 |
| `market/a_share/daily_basic/` | 每日指标（市盈率、市净率、市销率、股息率、换手率、市值），同一区间 |
| `market/a_share/index/` | 沪深300 指数（2005 年起）与历史成分股（2010 年起） |
| `market/a_share/calendar.parquet` | 交易日历 |
| `csi300_lightgbm_ensemble_model_walkforward/` 等 | 旧模型文件（离线流程逐年滚动训练，原样导入，已有成绩可复现） |
| 其余 `*.parquet` | 旧离线流程的历史数据与训练样本，供核对与追溯 |

有了数据包，**不需要任何密钥**就能运行全部功能、复现全部成绩卡。

## 可选：补到最新交易日

数据包截至 2026-09-23。想补到最新，在 `backend/.env` 里填 tushare 的 token（参照 `.env.example`）：

```
TUSHARE_TOKEN=你的token
TUSHARE_HTTP_URL=https://tuaremax.top
```

服务启动时会自动补齐到最近交易日（每个交易日约 3 次调用：日线、复权因子、每日指标），也可以在"数据与模型"页手动补齐。`.env` 不会提交到仓库；用 Docker 部署时，同名环境变量通过 `docker-compose.yml` 传进容器。

## 运行时产生的文件

- `backend/data/patience_quant.db`：数据库（策略、回测记录、模拟盘、大模型设置）。第一次启动时自动创建并登记内置策略。
- `backend/data/models/`：系统内训练的模型。内置的模型策略只记录训练设置，缺失的模型在第一次启动时自动排队训练（每个 1.5～6 分钟），训练完自动计算成绩卡（ADR-0053）。测试环境用 `PATIENCEQUANT_AUTO_TRAIN=0` 关闭。

这两样都不进仓库。

## 一键复现成绩卡

```bash
make reproduce     # 等同于 cd backend && python scripts/reproduce.py
```

初始化数据库、训练内置模型、计算 26 个策略的成绩卡，再与 `docs/成绩卡快照.json` 按策略逐项对比，输出"一致 / 接近 / 不同"。快照在 Python 3.13、LightGBM 4.7.0、XGBoost 3.4.1、torch 2.11（CUDA 12.8，RTX 4090）下生成，依赖版本见 `backend/requirements-lock.txt`。LightGBM 与因子策略应当完全一致；XGBoost 在 GPU 与 CPU 上、LSTM 在不同显卡上可能有细微差别。

## 交给 Docker 部署

`docker-compose.yml` 把后端数据目录绑定到宿主机：

```yaml
volumes:
  - ./backend/data:/app/data
```

先在宿主机上 `make data`，`docker compose up --build` 启动的容器就能直接使用。Docker 镜像不包含训练依赖（torch），需要系统内训练时请用 `make setup` 的本机环境。

## 大模型设置不需要重启

`OPENAI_API_KEY` / `OPENAI_BASE_URL` / `OPENAI_MODEL` 可以在前端"AI 工具"页配置，保存后立即生效。`.env` 里的值作为没在前端配置过时的默认值。
