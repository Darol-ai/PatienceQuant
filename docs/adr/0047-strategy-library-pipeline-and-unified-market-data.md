# 策略库流水线 + 行情数据统一（取代 ADR-0001 的范围限定）

## 背景

ADR-0001 把本期范围限定为"课程作业要求的一条纵切"：只做 A 股、一套自有策略、用模拟盘充当验收里的实盘。之后项目里陆续长出了多种策略（因子权重的多因子 V3、沪深300 LightGBM/XGBoost/集成、30 支候选池回归模型），但它们各有一套取数、打分、选股、下单的写法，互不相通；行情数据也分成两条路径——看板/股票池/多因子策略用 SQLite 按需拉取，模型策略在运行时直接读离线脚本生成的 parquet 文件，后者服务从不更新（模拟盘日期卡在 2026-09-11 即由此而来）。

本次调整的目标不再是某一个策略，而是一个能容纳多种策略、多个市场、支持用户自定义和智能体推荐的策略平台。仍然定位为课程演示，不接券商、不动真钱。

## 决定

1. **市场范围**：A 股 + 港股通标的。每个策略只属于一个市场，不做跨市场混合持仓（避免币种换算、交易日历和交易规则混在一个账户里）。港股能否落地取决于数据源能否拿到港股列表（含每手股数）和日线，待验证。

2. **统一的策略流水线**。每个策略都由同一组插槽组成：

   ```
   本地行情库 → 因子 → 打分 → ① 选股规则 → ② 权重方案 → ③ × 择时仓位 → ④ 调仓 → 订单
   ```

   - **打分**是因子权重策略和模型选股策略的共同接口：输入该策略声明需要的因子，输出"每支股票一个分数"。因子的种类和个数由策略自行声明，后续环节只认分数，所以不同策略的因子可以完全不同；任何模型只要满足"输入因子表、输出分数"即可接入。
   - **择时信号**是另一个独立插槽：输入指数数据，输出 0～100% 的整体持仓比例；决定买多少，不决定买哪些。不选则满仓。
   - ① 选股规则：前 N 名 / 前 x%。不提供"分数超过某值才买"，因为不同模型、不同因子组合的分数量纲不同，用户无法给出有意义的阈值。
   - ② 权重方案：等权 / 按分数加权，外加单股上限。
   - ④ 调仓：只对目标持仓与当前持仓的差额下单，比例变化小于换手阈值的不动，数量按各市场最小交易单位取整。

   这是本次改造中最难反悔的决定：之后所有策略、模型、择时信号都按这个契约接入。

3. **策略制定与策略实践分开**。市场、打分方式、择时信号、选股规则、权重方案、调仓频率属于策略本身，存进策略库；改任何一项都是另存新策略。回测起止日期、初始资金、股票池、费用属于每次回测。这样策略库里每个策略的回测结果可复现，每次回测结果都保存、可随时调出。

4. **行情数据只有一个来源：本地行情库**（Parquet，按年份分文件，2016 年起，A 股全市场 + 港股通标的，按交易日批量从 tushare 拉取）。SQLite 只保存业务数据，删掉其中的行情缓存表。启动时检查本地最新日期与最近交易日，落后就补齐；运行中可手动补齐。部署前构建好的行情库随仓库经 Git LFS 推送，之后每天新增的数据只补到本地、不再推送。

   不把行情放 SQLite 的原因：千万行级的 SQLite 是单个大文件，每次补数据整个文件都变，推到 LFS 就是一个新版本，额度很快耗尽；按年分文件的 Parquet 每天只改当年一个文件。起始年份定在 2016 而不是 2010，也是为了控制在 GitHub 免费 LFS 额度（1GB）以内。

5. **停用离线脚本**。48 个离线脚本（抓数据、构建训练集、训练、逐年回测）及 `prepare_real_data.sh` 从工作目录删除（删除前先提交当前版本，历史可找回）。抓数据逻辑并入本地行情库的补齐功能，训练逻辑并入系统内的训练功能，逐年回测由回测中心取代。

6. **模型只能在系统内训练**：用户可选模型类型（LightGBM / XGBoost / LSTM / Transformer）、输入因子、预测天数、市场和股票池、训练年份；滚动训练方式固定（每年只用之前的数据训练、在之后一年评估），防止误设成偷看未来的训练方式；只开放 2～3 个关键超参数；同一时间只跑一个训练任务。训练完成自动登记进模型库，带样本外成绩。

7. **现有模型两个都保留**：此前离线流程训练的模型作为"旧模型"原样导入模型库，保证沪深300 集成策略的已有成绩（年化 29.5%）可复现，运行时改从本地行情库读数据；同时用新训练功能在相同设置下、2016 年起的数据上重训一版，与旧模型并排对比，作为新训练功能的验收。两者差距大时如实记录原因。

8. **智能体推荐**：先问用户偏好（市场、可接受回撤、持仓周期），再按每个策略成绩卡上的事实数据筛选排序；大模型只负责对话和解释，引用的数字只能来自成绩卡。本期只推荐单个策略加建议参数。智能体不能直接下单。

9. **策略库第一批约 10 个**：迁移现有 5 个（沪深300 LightGBM / XGBoost / 集成、30 支候选池回归、多因子 V3），加 QuantsPlaybook 里只用日线数据即可实现的 3 个择时信号（RSRS、均线、鳄鱼线）和 2 个选股因子（上下影线、振幅）。QuantsPlaybook 作者已同意直接使用其代码，仓库中加 `NOTICE` 注明出处；其代码原本从聚宽取数，需改为读本地行情库并包装成打分或择时接口。

10. **拿掉多因子 V3 里的 LightGBM 层**。该层在每次调仓时用当天的因子分做输入、用同一批因子分的三分位做标签、在同一批数据上训练后立即预测，不含任何关于未来的信息；页面宣称的"p_up≥60% 且 p_down≤25% 用于入场"实际也未参与选股。多因子 V3 以纯因子权重策略的形式进入策略库。

## 后果

- 模型选股策略最早只能从 2019 年左右开始回测（需 120 天特征窗口加至少 2 年训练数据）；因子权重和择时策略约从 2016 年下半年开始。回测页面按所选策略自动限制最早日期。
- 模型策略运行时改读本地行情库，行情库每天自动补齐，模拟盘日期不再停在离线文件的最后一天。
- 本期不做：真实交易、语音交互、多策略组合、跨市场持仓。
