# V3 入场门槛改用训练集分位数；修复引擎"提前算完所有调仓权重"的时序 bug

## 背景一：V3 原文的绝对概率门槛在这套模型约束下摸不到

用真实数据训练+校准 LightGBM 三分类模型后实测发现：训练集 17757 条样本里，
**0 条**达到 V3 文档写死的 `p_up>=0.60`；样本外（2024下半年~2025）的 IC
更是从训练/校准区间的 0.21~0.27 掉到 -0.008（和零没有区别）。

进一步排查确认这不是训练不够/泛化失败能解释的：**就算是模型见过的训练集本身
（理论最佳情况）也摸不到 0.60**。根因是 V3 自己定的两条硬约束放在一起造成的
结构性矛盾——`num_leaves=7/max_depth=3` 的浅层模型（3.3 节，为了防止过拟合）
天然给不出很尖锐的概率分布，而 UP 事件的基础概率只有约 12%（三分类里的少数
类），一个刻意浅、不过拟合的模型很难对少数类给出 60% 以上的置信度。

## 决定一：入场门槛换成训练集分位数

`p_up_threshold` = 训练集（校准后）p_up 的 90 分位（≈0.19）；`p_down_threshold`
= 训练集（校准后）p_down 的 25 分位（≈0.21）。规则在看回测结果**之前**、只用
训练集分布定死，不是看哪个数字能让回测出交易再拼凑一个。`quant_v3/entry_signal.py`
的 `entry_approved()` 和 `V3Strategy` 都改成参数可覆盖，默认值仍是 V3 原文的
0.60/0.25——这样任何人不传自定义阈值时，行为还原成 V3 文档字面意思。

## 背景二：BacktestEngine 提前把所有调仓日的权重都算完了

`BacktestEngine.run()` 原来的实现分两阶段：先一次性遍历全部调仓日调用
`strategy.generate_weights()`（此时还没有任何交易真正执行），再逐日回放执行
交易。这对无状态的 `MultiFactorStrategy`（每次只看 `as_of` 和市场数据，不看
自己的持仓历史）没问题，但 `V3Strategy` 靠 `self.positions`（由 `notify_fill`
维护）判断"这只股票是不是已经持有"——当 `generate_weights` 在提前遍历阶段被
调用时，`self.positions` 永远是空的，因为对应的 `notify_fill` 要等到后面的
逐日回放阶段才会触发。

现象：给"月末未达买入条件不自动清仓"这条规则写的修复代码测试全过，但接进真实
回测后完全没生效——已持仓股票下个月没有再次通过入场门槛就被引擎当成"目标权重
掉到 0"直接清仓了，触发原因是引擎的通用调仓文案（"目标权重下降"），不是
`on_daily_close` 该走的强制退出路径。

## 决定二：`generate_weights` 改成惰性求值

调仓权重的计算挪到逐日回放循环内部，走到某个执行日才当场调用
`strategy.generate_weights()`，不再在开头一次性预先算完全部调仓日。这样有状态
的策略在调仓时看到的 `self.positions` 是当时真实已经回放出来的持仓，不是还没
执行到的未来状态。改动只挪了调用时机，`MultiFactorStrategy` 的输入输出不受
影响（回归测试 90/90 全绿，行为不变）。

## 影响

这两个修复合起来，A 阶段回测从"零成交"→"引擎 bug 导致一买一卖两笔、错误平仓
本该持有的仓位"→"一笔买入、正确持有到回测结束（收益 1.57%）"。

## 后续：补上 V3 7.2 节的逐年滚动训练（见 `scripts/train_v3_walkforward.py`）

样本外 IC≈0 的根因排查到"单次静态切分、模型对 2024-2025 两年都用同一个
2023 年定型的模型"——换成 V3 7.2 节原本要求的逐年滚动（训练截止 Y-1年7月、
Y-1下半年校准、预测年度Y），2024 年模型的样本外 IC 从 -0.008 变成
**0.1748**（p≈5e-18，真实显著），2025 年模型仍然只有 -0.035（不显著）——
说明这类纯技术面特征的信号衰减很快，滚动重训是必需的，不是锦上添花，但即使
滚动重训也不能指望信号能撑过一年以上。

`V3Strategy` 新增 `threshold_source` 参数（`as_of -> (p_up_th, p_down_th)`），
支持逐年不同的门槛；`quant_v3/model_training.py` 把训练逻辑抽成可复用的
`train_fold()`，`quant_v3/walkforward_signal.py` 按年份分发到对应的模型。

补上滚动训练后，2024-2025 回测产出 **4 笔交易（3 买 1 卖），其中一次
`HARD_STOP_LOSS` 真实触发**（600309.SH 跌约 17% 正确离场），总收益
**-0.94%**（小幅亏损）。如实报告：滚动训练让模型和风控机制都被真实验证到，
但最终两年净收益仍是负的——没有为了让数字转正而继续调门槛/参数。
