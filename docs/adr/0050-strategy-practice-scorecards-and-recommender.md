# 策略制定/实践页面、成绩卡与智能体推荐

## 背景

ADR-0047 第 3、8 条：策略制定与策略实践分开，每次回测都保存可调出；智能体先问偏好，再按成绩卡上的事实筛选排序，大模型只负责解释，只推荐单个策略，不能下单。

## 决定

1. **策略制定**（原"策略中心"页）：从策略库选一个起点，按 打分 / 选股 / 权重 / 择时 / 调仓 五步配置，保存时一律另存为新策略（同名则版本号加一），已保存的策略不再修改。没有真实数据的因子在表单上如实标注。接口：`GET /pipeline/options`、`POST /strategies/spec`。

2. **策略实践**（原"回测中心"页）：回测只填区间、资金、股票池、费用；持仓数量、单股上限、调仓频率等都来自策略规格，表单上不再提供覆盖。每次回测的完整结果都从数据库读取返回，所以刚跑完看到的和之后从"回测历史"里调出来的是同一份。接口：`GET /backtests?strategy_id=`、`GET /backtests/{id}/result`。

3. **成绩卡**：每个策略在同一套标准条件下回测一次——2019-01-01～2025-12-31、100 万、手续费 0.1%、滑点 0.05%、策略自己的默认股票池。成绩卡本身就是一次普通回测（出现在回测历史里），config 里记着"策略规格 + 默认股票池 + 标准条件"的指纹，任何一项变了旧成绩卡自动失效。后台一次只算一个。接口：`GET /scorecards`、`POST /scorecards/refresh`。

4. **推荐规则全部写死在代码里，并原样展示给用户**：只看同一市场、已有成绩卡的策略 → 最大回撤不超过用户能接受的值（都不满足时给回撤最小的一个，并说明超出了范围）→ 优先调仓频率与持仓周期一致的（都不一致时说明忽略了这一条）→ 按夏普比率排序取第一个，另列两个备选。

5. **大模型只写解释，而且数字要经过核对**：回答里每个百分比都必须能在成绩卡事实、用户偏好或筛选规则里找到（允许 0.1 个百分点的舍入差），否则丢弃它的回答，改用规则生成的解释，并在页面上说明；被丢弃的原文只存进审计记录。没有配置大模型时直接用规则解释。每次推荐都记一条审计记录（偏好、选中的策略、所用成绩卡、规则）。智能体只给出"去策略实践回测"的入口，不调用任何下单接口。

## 验证

- 10 个内置策略的成绩卡全部基于真实行情算出，数字与 ADR-0048/0049 的单独回测一致。
- 真实大模型的第一次回答被数字核对拦下，原因是它复述了用户自己说的"−25%"，而允许清单里当时漏了用户偏好；补上之后第二次回答通过核对，引用的累计 306.0%、超额 250.1% 等都来自成绩卡。
- 测试不再读取 `.env` 里的真实大模型 key（conftest 置空），大模型分支用假客户端测。

## 后果

- 多因子 V3 的默认股票池是"大盘股核心池"（通用目录按代码顺序的前 300 支，只是代理），它的成绩卡是年化 3.9%、最大回撤 −61.3%；同一策略在真实沪深300 成分股上是年化 19.9%。是否改默认股票池待定。
- 早先点"保存并回测"留下的 6 个 V3 副本没有算成绩卡，需要时在推荐面板点"计算缺少的成绩卡"。
