# 撤回：广度自适应Top-K的"提升"是ADR-0019那个bug的假象

## 背景

ADR-0019 修复了 `APhaseDataService.benchmark()` 的等权重计算bug。策略
自身的收益(`strategy_return`)从来没受这个bug影响（bug只在基准计算里），
但"跑赢/跑输基准"的判断（`excess_return`/胜负计数）全部依赖这个曾经
错误的基准，包括 ADR-0018 选择 `breadth_threshold=0.7` 时用的"跑赢年数
从4/7提升到5/7"这个关键依据。

## 重新核对

用修复后的真实基准（2019~2025逐年：+63.5%/+64.0%/-1.9%/-12.6%/+8.5%/
+23.3%/+31.4%），重新核对 ADR-0018 网格里四个配置（策略自身收益全部
是修复前跑出来的原始数字，不受bug影响，可以直接复用）：

| 配置 | 跑赢年数(真实基准) | 7年复合收益 |
|---|---|---|
| 不加广度机制(ADR-0016基线) | 4/7 | **+293.5%（最高）** |
| breadth_threshold=0.7(ADR-0018选定) | 4/7 | +289.2% |
| breadth_threshold=0.8 | 4/7 | +276.6% |
| breadth_threshold=0.9 | 4/7 | +271.5% |

**四个配置在真实基准下全部并列4/7年跑赢，且不加广度机制的最简单版本
总收益反而最高**。ADR-0018 报告的"5/7年、广度机制显著提升胜率"完全是
基准计算bug造成的假象——不是广度自适应本身没用对参数，是这个机制在
真实基准下根本没有产生任何可衡量的正贡献。

## 结论

撤回 ADR-0018 的机制选择，`breadth_threshold` 参数保留在代码里（默认
`None`，已经是默认值，行为不受影响），但不再作为当前推荐配置的一部分。
**当前最佳配置回退到 ADR-0016 的版本**：30支候选池+扩展历史(2010起)+
horizon=90+top_k_ratio=0.7+等权重+无趋势过滤+不加广度机制。

`scripts/run_broad_regression_per_year_backtest.py` 的 `BREADTH_THRESHOLD`
常量改回 `None`。

## 诚实结论（当前状态）

**4/7年跑赢真实基准，7年复合收益+293.5%，仍落后真实基准+303.9%约10个
百分点**。2019/2023/2025三年跑输，2019(-20.9%超额)差距最大，2023/2025
差距很小(个位数百分点)——后两个是接近打平的年份，比2019更有希望通过
后续优化补齐。
